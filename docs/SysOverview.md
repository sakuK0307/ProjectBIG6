# システム構成図（System Overview）

## 1. システム概要

本プロジェクトでは、大学生の履修登録を支援するWebアプリケーション「履修下書きアプリ」を開発する。

履修登録の下書き作成や単位状況のシミュレーションを提供し、履修登録に伴う操作の負担を軽減することを目的とする。

## 2. システム構成

元資料のシステム構成図では、以下の要素が示されている。

| 構成要素 | 役割 |
|---|---|
| 学生 | アプリの利用者。下書きの作成や履修状況の確認を行う |
| 履修下書きアプリ | 履修計画の作成・閲覧、単位状況のシミュレーションを提供する |
| シラバス | 履修計画に必要な授業情報の参照先 |
| 履修モデル | 履修計画や単位状況の確認に用いる参照データ |
| 学務システム | 履修登録先となる大学のシステム |

## 3. 主な機能

### 3.1 下書き機能

学生が履修登録の下書きを作成し、内容を確認できる機能。

元資料では、下書きの作成・閲覧に加え、学生からの入力方法として以下が挙げられている。

- 下書きへの書き込み
- 成績PDFの反映
- Excelのインポート

### 3.2 単位状況シミュレーション

履修状況や履修計画をもとに、単位の取得状況を確認する機能。

履修モデルを参照し、学生が履修計画を立てる際の判断を支援する。

### 3.3 シラバスの参照

科目に関する情報をシラバスから参照する。

参照方法や取得する情報の範囲については、今後検討する。

### 3.4 学務システムとの連携

作成した下書きを学務システムでの履修登録につなげる。

元資料には「履修登録」として示されているが、具体的な連携方法は決定していない。

## 4. データの流れ

1. 学生が履修下書きアプリにアクセスする。
2. 学生が履修計画の下書きを作成・編集する。
3. アプリが履修モデルを参照し、単位状況のシミュレーションを行う。
4. 必要に応じてシラバスの情報を参照する。
5. 学生が下書きやシミュレーション結果を閲覧する。
6. 作成した履修計画を学務システムでの履修登録に利用する。

※ 上記は元資料の構成要素をもとに、想定される利用の流れとして整理したものである。

## 5. 今後の検討事項

以下は元資料では具体的な実装方法が定義されていない項目である。

- 下書きデータの保存先と保存形式
- 成績PDF・Excelの取り込み方法
- 履修モデルのデータ構造
- シラバスの参照方法
- 学務システムへの転写・連携方法
- 単位状況シミュレーションの判定条件
- ユーザー認証の必要性

## 6. まとめ

本システムは、履修登録の下書き機能と単位状況シミュレーションを中心として構成される。

シラバスや履修モデルを参照しながら履修計画を作成し、最終的に学務システムでの履修登録につなげることを目指す。

現段階ではシステム全体の概念的な構成が示されており、具体的な技術構成やデータの保存方法については、今後の設計で決定する。
