# 履修リスト画面の解説

履修リスト画面（`templates/list.html`）は、科目ごとに「いつ履修するか」「何点だったか」を入れると、単位の合計と、進級・卒業などの判定がその場で変わる画面です。

このドキュメントでは、画面を作っているファイルそれぞれの役割と、画面の機能、なぜそう作ったかを説明します。

## 1. 全体像

```
ブラウザ                                                     サーバー（今はモック）
┌──────────────────────────────────────────────┐            ┌────────────────────────────┐
│ list.html（骨組み）＋ list.css（見た目）       │            │ test/mock_api/list_mock.py │
│   │ 読み込む                                  │            │   画面のファイルを配信       │
│   ├─ pdf-import.js（PDF の読み取り）          │            │   GET /api/courses         │
│   └─ list.js（画面の動き）                    │            │   GET /api/plan            │
│        ├ import list-rules.js（判定の計算）   │            │   PUT /api/plan            │
│        └ import list-api.js ──── fetch ──────────────────▶│                            │
└──────────────────────────────────────────────┘            └────────────────────────────┘
                                                                  ▲ 科目データ
                                                    scripts/data/course.json（scripts が作る）
```

### ファイルの一覧

| ファイル | 役割 |
|---|---|
| `templates/list.html` | 画面の骨組み（上部バー・一覧の箱・サイドバー・ダイアログ） |
| `templates/css/list.css` | 見た目（色・並べ方・行の色・サイドバーの出し方） |
| `templates/js/list.js` | 画面の動き（表示・入力・保存・サイドバー・PDF 取り込みの画面） |
| `templates/js/list-rules.js` | 決まりごとと判定の計算（画面に触らない） |
| `templates/js/list-api.js` | サーバーとのやり取り（URL・fetch を知っているのはここだけ） |
| `templates/js/pdf-import.js` | 成績通知書・履修登録の PDF を読み取る |
| `test/mock_api/list_mock.py` | モックのサーバー（画面の配信と API。API の約束もここに書いてある） |
| `scripts/data/course.json` | 科目データ（scripts が Excel・時間割表・手で書いたファイルから作る） |

### 開き方

```powershell
python test/mock_api/list_mock.py
```

`http://localhost:5002/` を開きます。Flask で開く前提なので、HTML をダブルクリックしても動きません（データをサーバーから受け取るため）。
本物のサーバーができたら、モックの代わりにそれを起動します。HTML・CSS・JS は変えません。

### 読み込みの順番

`list.html` は `pdf-import.js`（`defer`）と `list.js`（`type="module"`）の 2 つを読み込み、`list-api.js` と `list-rules.js` は list.js が `import` します。
`defer` もモジュールも「HTML を読み終えてから、書いた順に実行する」ので、list.js が動くときには `window.PdfImport` がもう使えます。

### なぜファイルを分けたか

- **list-api.js**：list.js は URL や fetch の書き方を知りません。サーバーがモックから本物に変わっても、URL が変わっても、直すのは list-api.js だけで済みます。
- **list-rules.js**：卒業判定の計算は、いちばん間違えると困るところです。画面の処理と分けて「引数だけから結果を返す関数」にしておくと、画面を動かさずに計算だけを確かめられ、テストも書きやすくなります。
- **rules.json・course.json**：便覧で決まる数（進級の 62 単位など）や科目の情報は、JS に書かずにデータの側に置いています。便覧が変わっても、JS を直さずにデータを作り直せば済みます。

## 2. ファイルごとの説明

### 2.1 list.html（画面の骨組み）

中身は「箱」だけで、科目の行や判定は list.js が作って入れます。Jinja（`{{ }}`）は使わず、Flask はこのファイルをそのまま返します。

| 部分 | 主な要素（`id`） | 中身 |
|---|---|---|
| 上部バー（`header.topbar`） | `pdfImportBtn`・`pdfInput`、`entranceYear`、`courseType`、`headerTerm`、`sidebarToggle` | 表示A〜C、送信・PDF読込・Excel読込、入学年度・コース・今の学期の選択、サイドバーを開くボタン |
| 一覧の上の欄（`.list-toolbar`） | `search`、`deptFilter`、`progFilter`、`showFilter`、`sheetTotal` | 検索・絞り込みと、単位の合計 |
| 一覧（`section.pane-list`） | `sheetScroll`（スクロールする箱）、`sheetBody`（科目の行が入る） | 科目の行 |
| 卒業判定サイドバー（`aside.sidebar`） | `sidebarCourse`、`yearTable`、`progList`、`judgeList`、`sidebarClose` | 学年ごとの単位・プログラムごとの要件・進級などの判定 |
| そのほか | `popover`、`toast`、`importDialog`・`importBody` | 科目の詳細の窓、下に出る知らせ、PDF の読み取り結果のダイアログ |

- **`data-stub` が付いたボタン**（表示B・C、送信、Excel読込）は、まだ作っていない機能です。押すと「まだ実装されていません」と出ます。
- **入学年度・コース・学期の選択肢**は HTML に書いてあります。list.js が保存済みの値に合わせて選び直します。
- **部門の選択肢**は「すべての部門」だけ書いてあり、残りは list.js が科目データから足します。
- **`aria-label`・`aria-expanded` など**：画面の読み上げソフトに、欄の意味やサイドバーが開いているかを伝えるためのものです。
- **PDF のダイアログ**は `<dialog>` の中に `<form method="dialog">` があり、ボタンを押すとダイアログが閉じる作りです。

### 2.2 list.css（見た目）

- **色は変数で決める**：`:root` に `--bg`（背景）、`--accent`（強調の青）、`--plan`（予定の黄色）、`--mark-req`（必修・不可の赤）などを決め、ほかの場所は変数で色を指定しています。
  - **ダークモード**：`@media (prefers-color-scheme: dark)` で変数の値だけを入れ替えています。パソコンの設定が暗い色なら、画面も自動で暗くなります。
  - **なぜ変数か**：色を変えたいときに 1 か所直すだけで済み、ダークモードも変数を入れ替えるだけで作れるからです。
- **画面全体の並べ方**（`.app`）：上部バーとその下の一覧を、`grid` で縦に並べています。一覧の部分（`.list-scroll`）だけがスクロールし、上部バーは動きません。
- **一覧の見出し**（`.group-head`）：`position: sticky; top: 0;` で、スクロールしても一覧の上に残ります（「総合基礎部門」など）。
- **科目の行**（`.course`）：1 科目を 1 行に収めるように、科目名・タグ・入力欄を横に並べています（狭いと折り返す）。スクロールを減らすためです。
  - **行の左の線の色**で状態が分かります：`is-pass`（修得）は緑、`is-fail`（不可）は赤、`is-plan`（予定）は黄土色。
  - **状態の文字**（`.status`）も同じ色です。
- **タグ**（`.tag`）：区分（`kind-必修` は赤、`kind-選必` は青）、プログラム指定（`p-◎` は青の背景、`p-※` は紫、`p-○` は点線）、標準の学期（今の学期なら `is-now` で青）、自由科目（点線）、数えない科目（赤）。
- **点数の欄**：学期を選ぶまで入力できない状態（`:disabled`）は灰色、範囲外の数（`:invalid`）は赤い枠になります。
- **科目の詳細の窓**（`.popover`）：`position: fixed` で、押した科目名の近くに浮かせて出します（置く場所は list.js が決める）。
- **卒業判定サイドバー**（`.sidebar`）：
  - **幅 900px 以上**：右に 320px の幅で出し、一覧をその分だけ右から縮めます（`.app.has-sidebar > .pane { margin-right: 320px; }`）。一覧を隠さずに、入力しながら判定を見られるようにするためです。
  - **幅 900px 未満**：画面の下半分に出し、一覧を上半分に縮めます。
- **幅 640px 以下**（スマホなど）：入力欄を行の幅いっぱいに広げ、余白を減らします。
- **PDF のダイアログ**（`.import-dialog`）：画面の幅に合わせて最大 720px。結果の表は、見出しの行を `sticky` で残したままスクロールします。

### 2.3 list.js（画面の動き）

ES モジュールです。上から次の順に並んでいます。

1. サーバーからデータを受け取る（`DATA`・`SAVED`）
2. 画面が覚えている値（`state`）と、判定の材料（`context`）・保存（`save`）
3. 科目リストの表示と入力（`renderList`・`rowHtml`・`change` イベント）
4. 科目の詳細（ポップオーバー）
5. 上部バー・絞り込み・トースト
6. 卒業判定サイドバー（計算は list-rules.js、ここは HTML を作るだけ）
7. PDF の取り込み（読み取りは pdf-import.js、ここはダイアログと取り込み）
8. 最初の描画 `render()`

- **モジュールにした理由**：中で作る変数（`state` など）がほかの JS とぶつかりません。一番外側で `await` が使えるので、データが届くのを待ってから残りを始められます。
- **受け取れなかったとき**：一覧の場所に知らせを出し、`throw` で残りを実行しません（モジュールの一番外側では `return` が使えないため）。

機能ごとの説明は [4. 画面の機能](#4-画面の機能) にあります。

### 2.4 list-rules.js（決まりごとと判定の計算）

画面（`document`）にもサーバーにも触らず、引数だけから結果を返す関数（純粋な関数）だけを集めたファイルです。

| 種類 | 主なもの |
|---|---|
| 学期・点数 | `TERMS`、`TERM_LABEL`、`PASS`（60 点）、`termIndex`、`sortAttempts`、`cleanScore`、`fmtCredit` |
| コース・入学年度 | `ENTRANCE_YEARS`、`COURSE_TYPES`、`inCourseType`、`termsOf`、`notCountedFor` |
| 保存データ | `normalizePlan`、`readSavedPlan` |
| 修得・不可・予定 | `attemptStatus`、`summaryOf`、`counts` |
| 入力の注意 | `attemptWarning` |
| 卒業判定 | `REQS`（9 項目）、`PROGRAMS`、`makeContext`、`countedCourses`、`evaluate`、`judgments` |

- **便覧で決まる数は受け取る**：必要単位数・進級の単位数などはここに書かず、`rules`（サーバーの科目データの `rules`）として受け取ります。
- **判定の材料（context）**：`makeContext` が、今のコースの科目・数えるかどうかの判定・今のコースの必要単位数をまとめます。list.js は画面の `state` からこれを作り、`evaluate`・`judgments` に渡します。

### 2.5 list-api.js（サーバーとのやり取り）

`ListApi` を `export` していて、list.js が `import` して使います。

| 関数 | 送るもの | 返すもの |
|---|---|---|
| `getCourses()` | `GET /api/courses` | 科目データ `{ timetableYear, rules, courses }` |
| `getPlan()` | `GET /api/plan` | 履修計画 `{ term, entrance, courseType, plan }` |
| `savePlan(state)` | `PUT /api/plan`（履修計画を丸ごと） | 保存した履修計画 |

- **送り先**：画面と同じサーバーの `/api/...`（`BASE = ""`）。Flask で画面も API も配信するので、別のサーバーの URL を書かずに済み、CORS の設定もいりません。
- **時間切れ**：10 秒たっても返事がなければあきらめて、エラーにします（`AbortController`）。サーバーが固まっても、画面が待ち続けないようにするためです。
- **保存をまとめる**：学期や点数を続けて変えると `savePlan` が何度も呼ばれます。送っている途中に次が来たら、終わってから**最新のものだけ**を送ります。古い内容があとから届いて上書きされることがありません。
- **保存の失敗を知らせる**：失敗したら `listapi:save-error` という合図を `window` に送ります。list.js がこれを受け取って、トーストで「保存できませんでした」と出します。
- **エラーの中身**：サーバーが 400 などを返したら、返事の `error`・`details` をエラーに入れて投げます。

### 2.6 pdf-import.js（PDF の読み取り）

名城大学の「試験成績一覧表（成績通知書）」と「履修登録科目確認通知書」の PDF を読み取ります。`window.PdfImport` を作る、モジュールではない普通のスクリプトです。

```js
const result = await PdfImport.read(file, { courses, inCourseType, fallbackType });
// result = { kind, title, issued, entrance, courseType, grade, rows: [{ pdfName, course, term, score, result, code, note, problem }] }
```

- **PDF はブラウザの中だけで読む**：どこにも送りません（成績は個人情報なので）。
- **pdf.js を使う**：PDF から文字を取り出すライブラリです。「PDF読込」を押したときに初めて jsDelivr から読み込みます（ふだんの画面を重くしないため）。日本語のフォントを読むための対応表（cmaps）も同じ場所から読みます（cdnjs には cmaps がないため）。
- **文字を並べ直す**：pdf.js は文字を描いた順に返すので、表の列の順がばらばらになります。文字の位置（座標）で「上から下へ行ごと、行の中は左から右へ」並べ直しています。
- **書類の情報を読む**（`readMeta`）：発行日、入学年度（「入学年月日」か「適用カリキュラム年度」）、コース（「コース・専修：情報工学先進プロジェクトコース」。1 年次は「なし」）、年次。
- **どちらの書類かを見分ける**：「試験成績一覧表」か「履修登録科目確認通知書」の文字があるかで見分けます。
  - **成績**：「単位 年度 区分 期間 点数」の並びを探し、その前の語から科目名を見つけます。点数が `履修` なら履修中（予定）、`N` なら認定（60 点として取り込み）。学期は「年度 − 入学年度 + 1」で学年を出し、期間（前期・後期）と合わせて決めます。
  - **履修登録**：「講義コード 期間 区分 単位 科目名」の並びを探します。2 コマ続きの授業は 2 行出るので、講義コードで 1 つにまとめます。点数はないので予定として扱います。
- **科目名の照らし合わせ**（`normName`）：全角・半角をそろえ、`[遠]` や後ろの `*`、`（）` の注記、空白・中黒を取り、最後のローマ数字を数字にします（「英語コミュニケーション１」と「英語コミュニケーションⅠ」を同じにするため）。
- **コースで違う科目**：創造的思考法などはコースで別の行なので、PDF のコース（なければ画面で選んでいるコース）の科目を優先して照らし合わせます。
- **取り込めない行**：科目表にない、学期を決められない、点数を読めない行には `problem` を付けます。画面ではその行を赤くして、チェックできないようにします。

### 2.7 list_mock.py（モックのサーバー）

本物のサーバーができるまで、画面を動かすための Flask のサーバーです。

```powershell
python test/mock_api/list_mock.py
```

`http://localhost:5002/` で開きます。

- **画面も配信する**：`templates/` の中身を、URL のいちばん上から配信します（`/css/list.css`、`/js/list.js` など）。`/` には `list.html` を返します。
- **API の約束**：ファイルの先頭に書いてあります。本物のサーバーも同じ URL・同じ形で作れば、HTML・CSS・JS は変えなくて済みます。
- **科目データ**：`scripts/data/course.json` を起動したときに読み、`meta`（何から作ったかの記録）を外して `GET /api/courses` で返します。
- **履修計画**：メモリに置くだけです。止めたり再起動したりすると消えます。
- **値のチェック**：`PUT /api/plan` で送られてきた計画を `plan_problems()` で確かめ、学期・入学年度・コース・点数がおかしければ 400 と、どこがおかしいか（`details`）を返して保存しません。

## 3. データの形

### 科目データ（`GET /api/courses`、`scripts/data/course.json`）

```js
{
  meta: { source: [ … ] },      // 何から作ったかの記録（モックは返す前に外す）
  timetableYear: 2026,          // 時間割表の年度（開講クラス・シラバスのリンクがいつのものか。入学年度とは別）
  rules: {                      // 判定の決まりごと
    requirements: {             // 必要単位数（9 項目）。卒業判定 Excel から
      advanced: { PC: [10, 20, 8, 12, 21, 14, 9, 15, 104], DE: […], HM: […], NS: […] },
      general:  { PC: [10, 20, 8, 12, 10, 16, 9, 20, 104], … },
    },
    notCounted: [ … ],          // 入学年度の決まりで数えない科目（rules.json）
    judgments: { … },           // 進級などの条件の数（rules.json）
  },
  courses: [ … ],               // 科目の一覧（151 科目）
}
```

科目 1 つ（`courses` の 1 件）はこんな形です。

```js
{
  id: "r6", name: "英語コミュニケーションⅠ",
  dept: "総合基礎部門", group: "",        // 部門・科目群（見出しになる）
  kind: "選必", credits: 1,              // 区分・単位数
  terms: ["1前"],                        // 標準の学期
  prog: { PC: "", DE: "", HM: "", NS: "" },  // プログラム指定（必・◎・※・○）
  req: ["総選", "総計"],                  // どの集計区分に数えるか
  hidden: false,                         // 卒業判定 Excel で非表示の行か（総合コース用の行）
  courseType: "both",                    // どちらのコースで使うか："both"・"advanced"・"general"
  dsai: false,                           // DS・AI 教育プログラムの科目か
  offers: [ { code, label, sem, day, period, slots, room, teacher, ... } ],  // 開講クラス
}
```

### 履修計画（`GET /api/plan`・`PUT /api/plan`）

```js
{
  term: "3前",            // 上部バーの「今の学年・学期」
  entrance: 2025,         // 入学年度
  courseType: "advanced", // advanced（先進）か general（総合）
  plan: {                 // 科目 ID → 履修した回の一覧
    r6: { attempts: [{ term: "1前", score: 85 }] },                     // 1前で 85 点
    r7: { attempts: [{ term: "1後", score: 45 }, { term: "2後", score: null }],  // 不可 → 再履修予定
          code: "641201" },                                             // 選んだクラスの講義コード
  },
}
```

- `attempts` は再履修を含む「履修した回」で、いつも学期順に並べています。
- `score` が `null` の回は「予定」（まだ点数がない）です。

**なぜ回の一覧にしたか**：同じ科目を不可のあと取り直すことがあるからです。最初は「学期 1 つ」、次に「学期と点数 1 つ」でしたが、再履修を表せないので今の形にしました。

### 画面が覚えている値（list.js の `state`）

```js
const state = {
  term: "3前",            // 上部バーの「今の学年・学期」
  entrance: 2025,         // 入学年度
  courseType: "advanced", // advanced（先進）か general（総合）
  plan: {},               // 履修計画（科目 ID → 履修した回の一覧）
  search: "", dept: "", prog: "", show: "",   // 検索・絞り込み（保存しない）
};
```

履修計画の 4 つ（`term`・`entrance`・`courseType`・`plan`）と、検索・絞り込みの 4 つ（`search`・`dept`・`prog`・`show`）です。検索・絞り込みは保存しません（開き直したら全部表示に戻る）。

## 4. 画面の機能

### 4.1 起動とデータの受け取り

```js
[DATA, SAVED] = await Promise.all([ListApi.getCourses(), ListApi.getPlan()]);
```

- 科目データと履修計画を、**同時に**頼んで両方届くまで待ちます（順番に頼むより早い）。
- 受け取れなかったら、一覧の場所に「サーバーからデータを受け取れませんでした」と出して止まります。

**自由科目（便覧にあって Excel に無い科目）**

数学基礎演習Ⅰ・Ⅱ、モバイルアプリ開発 A・B など 10 科目は、学生便覧にはあるのに卒業判定 Excel にはありません。
これらは `scripts/data/excel_extra.csv` に手で書いてあり、`excel_to_json.py` が Excel の科目と一緒に入れ、そのまま科目データ（`course.json`）まで届きます。list.js は、サーバーから届いた科目をそのまま使うだけです（`ALL_COURSES = DATA.courses`）。

- 自由科目は卒業に必要な単位数に入らないので、`req` は空、`kind` は「自由」です。記録のためだけの科目です。一覧には「卒業要件に数えない（自由科目）」のタグが付きます。
- 同じ科目群の最後の科目のうしろに入れています。**理由**：一覧の見出し（「専門教育部門　理工学基礎科目」など）が途中で分かれないようにするためです。
- モバイルアプリ開発 B は、2023 年度入学だけ標準が 2 年後期（`termsByYear`）です。
- 時間割表に載っている科目（数学基礎演習など 8 科目）には、ほかの科目と同じように開講クラスが付きます。

**なぜデータの側に置いたか**：画面の中で足すと、「どんな科目があるか」が画面とサーバーの 2 か所に分かれ、ほかの画面やサーバーからはこの 10 科目が見えなくなるからです。データの側に置けば、科目は 1 か所で管理でき、開講クラスも付けられます。

### 4.2 保存済みの履修計画を読み込む

サーバーから受け取った履修計画（`SAVED`）のうち、使える値だけを `readSavedPlan()`（list-rules.js）で取り出し、`state` に入れます。

- 学期・入学年度・コースは、使える値のときだけ入れます（おかしければ初期値の 3前・2025 年度・先進のまま）。
- 科目ごとの回は `normalizePlan()` で整えます。学期がおかしい回は外し、点数は 0〜100 の整数にそろえ（`cleanScore`）、学期順に並べます。
- 今の科目一覧にない ID は読み飛ばします。

**なぜ**：サーバーから届いたデータに少しおかしなところがあっても、画面が壊れずに動くようにするためです。

ブラウザ（localStorage）には保存しません。保存先はサーバーだけです。

### 4.3 先進プロジェクトコース／総合コースの切り替え

卒業判定 Excel では、コースで扱いが違う科目（必修か選択か など）を 2 行に分け、総合コース用の行を「非表示の行」にしています（`hidden: true`）。
科目ごとに、どちらのコースで使うかを `courseType` として科目データに入れてあり、画面はそれを見るだけです（list-rules.js の `inCourseType(c, type)`）。

| `courseType` | 先進で表示 | 総合で表示 | どう決まるか（`build_course_data.py`） |
|---|---|---|---|
| `general` | × | ○ | Excel で非表示の行（7 科目） |
| `advanced` | ○ | × | 総合用と同じ名前の行（6 科目）と、`rules.json` の `advancedOnly` に書いた科目（先進プロジェクト実験Ⅱ・先進プロジェクトゼミナール） |
| `both` | ○ | ○ | それ以外 |

- 例：創造的思考法・PBL 概論は、先進では必修、総合では選必・選択なので、同じ名前の行が 2 つあります。
- **なぜデータに書いたか**：画面で「総合用と同じ名前か」「『先進プロジェクト』で始まるか」と科目名の書き方で見分けると、便覧で名前が変わったときに間違えます。また、どの科目がどちらのコースのものか、データを見ても分かりません。
- 必要単位数も、先進は Excel の値、総合は Excel の「総合コース用」の列の値（専門必修 10、◎ 16、○ 20 など）を使います。

**なぜ両方の科目を持っておくか**：`byId` には両コースの全科目を入れています。コースを切り替えても、もう一方のコースで入れた予定・点数が消えないようにするためです。

### 4.4 入学年度の切り替え

2023〜2026 年度の学生便覧を比べると、必要な単位数と科目はほぼ同じです。入学年度で変わるのは次のところだけです。

- **2023 年度入学・先進コースの「情報技術の応用と職業」**：教職課程として履修はできますが、進級・卒業研究着手・卒業の単位には数えません（`notCountedFor`。どの科目を数えないかは `rules.json` の `notCounted`）。一覧に「卒業要件に数えない」のタグが付きます。
- **モバイルアプリ開発 B の標準学期**：2023 年度入学だけ 2 年後期です（`termsOf`）。
- 研究ゼミナールの判定で、2024 年度入学以降だけの決まりがあります（4.13 参照）。

### 4.5 科目リストの表示

`renderList()` が、今のコースの科目を順に 1 行ずつ作ります（`rowHtml`）。

- **見出し**：部門・科目群が変わるところに見出し（`group-head`）を入れます。CSS の `position: sticky` で、スクロールしても一覧の上に残ります。
- **1 行の中身**：
  - 科目名（押すと詳細が開く）
  - タグ：区分と単位数、プログラム指定（◎・※・○。「必」は出さない）、標準の学期（今の学期と同じなら強調）、自由科目・夏期集中などの注記
  - 履修した回ごとの「学期のプルダウン」「点数」「状態（修得・不可・予定）」
- **行の色**：科目全体の状態（`is-pass`・`is-fail`・`is-plan`）で色が変わります。

### 4.6 学期・点数の入力

一覧の中の変更は、`list` 全体の `change` イベントでまとめて受け取ります（5 章「イベントの委任」）。

| 操作 | 何が起きるか |
|---|---|
| 学期を選ぶ（初めて） | その学期の回を 1 つ作る（点数は空＝予定） |
| 学期を変える | その回の学期を変え、学期順に並べ直す。選んでいたクラス（`code`）は消す |
| 「未登録」にする | その回を消す。回がなくなれば科目ごと消す |
| 同じ科目で、もうある学期を選ぶ | 元に戻して「○年○期の回はすでにあります」と出す |
| 点数を入れる | 0〜100 の整数にそろえて入れる。空にすると予定に戻る |
| 点数の欄で Enter | 入力を確定する（欄から抜ける） |

- 学期を選ぶまで、点数の欄は入力できません。
- **クラスの選択を消す理由**：学期が変われば、開講しているクラスも変わるからです。

### 4.7 再履修

最後の回が不可（60 点未満）で、まだ修得していない科目には「＋ 再履修を追加」ボタンが出ます。

- 押すと、最後の回の**次の学期**を初期値にして、回を 1 つ足します。足した回の学期プルダウンに自動で移ります。
- 2 回以上あると、「初回」「再履修」「再履修2」…の印が付きます。

### 4.8 修得・不可・予定の判定

卒業判定 Excel と同じ決まりにしています。

- **60 点以上で修得**（`PASS = 60`）。
- **再履修したら、いちばん高い点数で判定**します。1 回でも 60 点以上なら修得です。
- **点数が空の回は「予定」**です。卒業判定では、予定の科目も「取れる見込み」として数えます（Excel で予定を 60 点として入れるのと同じ）。
- **単位を数える学期**（`countTerm`）：修得していれば最初に修得した回、まだなら予定の回の学期です。サイドバーの「学年ごとの単位」や、「○年○期までに」の判定に使います。

これらは list-rules.js の `summaryOf(p)` 1 か所にまとめています。**理由**：一覧・合計・サイドバー・判定で、同じ決まりを別々に書くと食い違うからです。

### 4.9 入力の注意（開講していない学期など）

予定の回（点数がまだない回）について、次の場合に「⚠」の注意を出します（`attemptWarning`）。

- **その学期に開講していない**：時間割表に前期のクラスしかないのに後期を選んだ、など。「後期は開講していません（2026年度の時間割表）」と出ます。
- **上の学年の科目**：2 年次の科目を 1 年で選んだ、など。コードは「開講クラスの学年（`grade`）、なければ標準の学期の学年」で判定する作りですが、今の科目データの開講クラスには学年が入っていないので、実際は標準の学期の学年で判定しています。

**点数を入れた回には出さない理由**：点数があるのは「実際に取った」記録です。時間割表は今年度のものだけなので、過去の年度とは開講学期が違うことがあり、正しい記録に注意を出してしまうからです。

### 4.10 検索・絞り込み

上の欄で、表示する科目を絞り込めます（`visible`）。保存はしません。

| 欄 | 絞り込み方 |
|---|---|
| 科目名で検索 | 名前に含まれる科目だけ |
| 部門 | 選んだ部門の科目だけ（選択肢は科目データから自動で作る） |
| プログラム | そのプログラムの指定がある科目だけ。タグもそのプログラムの印だけにする |
| 表示 | 登録済みだけ／未登録だけ／今の学期が標準の科目だけ |

「登録済みだけ」「未登録だけ」で絞っているときに学期を変えると、その科目が条件から外れることがあるので、一覧全体を描き直します。

### 4.11 単位の合計

一覧の上に「修得 ○ ＋ 予定 ○ 単位」を出します（`renderTotal`）。

- 数えるのは、今のコースの科目で、自由科目でなく、入学年度の決まりで外れないもの（`isCounted`）だけです。

### 4.12 科目の詳細（開講クラスとシラバス）

科目名を押すと、その近くに小さな窓（ポップオーバー）が開きます（`openCourseDetail`）。

- 区分・単位数・標準の学期、これまでの履修（「1年前期 45点、2年後期 予定」など）、プログラム指定
- **開講クラスの一覧**：「水3・4限 N-324 Aクラス・隔週A ／ 担当（講義コード）」の形で 1 行ずつ。
  - 履修予定（なければ標準）の学期のクラスを先に出します。**理由**：いちばん見たいのはその学期のクラスだからです。
- 各クラスを押すと、名城大学のシラバス（Campusmate-J）のその講義のページを新しいタブで開きます。URL には時間割表の年度（`timetableYear`）を入れます。
- 窓の外を押す、Esc、一覧をスクロールすると閉じます。

### 4.13 卒業判定サイドバー

右上のボタンで開きます。開いている間は、入力するたびに描き直します。

**① 学年ごとの単位**

1〜4 年の前期・後期ごとに、数える単位（修得と予定）の合計を表にします。今の学期の行を強調します。

**② プログラムごとの修了要件**（PC・DE・HM・NS）

- 9 項目（総合基礎 選択必修・合計、理工基礎 指定・選択必修、専門必修、プログラム指定 ◎・※・○、専門合計）ごとに「修得 / 必要」とプログレスバーを出します。
- 「修了」か「残り最低 ○ 科目」を出します。残り科目数は、卒業判定 Excel の M19〜M27 と同じ式で計算します（1 科目＝2 単位として、項目どうしの重なりを考えた式）。
- 開いているプログラムを覚えておき、描き直しても開いたままにします（最初は DE）。

**③ 進級・卒業などの判定**（学生便覧と Excel「総合判定」シートの条件）

| 判定 | 条件 | いつまでの分で数えるか |
|---|---|---|
| 3 年次への進級 | 情報工学基礎科目 3 科目以上、かつ 62 単位以上 | 2 年後期まで |
| 研究ゼミナールの履修 | 85 単位以上。2024 年度入学以降は、卒業研究を履修中・修得済みの学期には履修できない | 3 年前期まで |
| 卒業研究の着手 | 卒業まで残り最低 10 科目以内 | 3 年後期まで |
| 卒業 | 4 プログラムのどれか 1 つを修了 | 全部 |
| DS・AI サブカリキュラム | 対象科目 7 科目以上（登録者のみ） | 全部 |

- 計算は list-rules.js の `evaluate(ctx, upto)`（9 項目と残り科目数）と `judgments(ctx, all)`（進級などの判定）でしています。list.js はその結果を HTML にするだけです（`renderSidebar`・`judgmentsHtml`）。
- 「いつまでの分で」は `evaluate(ctx, upto)` の `upto` で、その学期までに数える科目だけで計算しています。
- 表の数（62 単位・85 単位・残り 10 科目・DS・AI の 7 科目、区切りの学期、2024 年度からの決まり）は `rules.judgments` から読んでいます。
- 「残り最低 ○ 科目」のように少ないほど良い値は、プログレスバーを逆向きに使います（`less: true`）。

**なぜサイドバーにしたか**：一覧で入力しながら、判定がどう変わるかを横で見られるようにするためです。閉じている間は計算しないので、一覧の操作が重くなりません。

### 4.14 保存

`save()` が、`term`・`entrance`・`courseType`・`plan` を丸ごとサーバーに送ります（`PUT /api/plan`）。

- 学期・点数・再履修の変更、上部バーの学期・入学年度・コースの変更、PDF の取り込みのたびに呼びます。
- 検索・絞り込みは保存しません（開き直したら全部表示に戻る）。
- 送る処理は list-api.js が裏で行います。続けて変更しても、最新のものが送られます。
- 保存に失敗すると、画面の下に「保存できませんでした」と出ます。

**なぜ丸ごと送るか**：変わった 1 科目だけを送るより作りが簡単で、サーバーと画面の内容が食い違いにくいからです。データも数 KB なので、毎回送っても問題ありません。

### 4.15 PDF の取り込み

「PDF読込」ボタンで、名城大学の次の PDF を読み取って取り込めます。読み取り自体は `pdf-import.js` が行います（2.6）。

- **試験成績一覧表（成績通知書）**：点数のある科目は、その学期の回の点数として入れます（同じ学期の回があれば上書き）。「履修中」は予定として入れます。
- **履修登録科目確認通知書**：登録した科目を、その学期の予定として入れます（点数のある回はそのまま）。

流れ：

1. PDF を選ぶと、読み取り中の窓が開く
2. 読み取り結果を表で出す（PDF の科目名、このアプリの科目、学期、結果）。取り込めない行は赤く、チェックできない
3. PDF の入学年度・コースが今の設定と違えば、「PDF に合わせる」チェックを出す
4. 「取り込む」で、チェックした行だけを入れて保存する

**PDF はブラウザの中だけで読み、どこにも送りません**（成績は個人情報なので）。取り込んだ結果の履修計画だけが、いつもの保存でサーバーに送られます。

**「取り込む」を送信の時点で処理する理由**：ダイアログを閉じたあとの `close` イベントが、環境によって届かないことがあったためです。

## 5. 画面の描き方の工夫

- **全体を描き直すか、1 行だけか**
  - 入力したときは、その科目の行だけ描き直します（`updateRow`）。**理由**：140 行以上を毎回作り直すと遅く、入力中の欄からカーソルが外れてしまうからです。描き直したあと、入力していた欄にカーソルを戻します。
  - コース・入学年度・絞り込みを変えたときは、表示する科目が変わるので全体を描き直します（`renderList`・`render`）。
- **イベントの委任**：プルダウンや点数の欄は、1 つずつではなく、一覧全体（`list`）でまとめて `change` を受け取ります。行を描き直しても、受け取りの登録をやり直さなくて済みます。
- **HTML の文字の無害化**：科目名などを HTML に入れるときは `esc()` を通します。`<` や `"` が入っていても、画面が崩れたり、意図しない HTML として動いたりしないようにするためです。
- **プルダウンの値は後から入れる**：HTML を作ったあとに `fillSelects()` で各回の学期を選択状態にしています。
