# KPT（Keep・Problem・Try）

## 1. 概要

本資料では、履修登録下書きアプリの開発に向けて実施したKPTの内容を整理する。

KPTは以下の3つの観点から、現状の方針を振り返り、今後の改善につなげるための手法である。

- **Keep**：継続したいこと、維持したい機能
- **Problem**：現状の問題点や課題
- **Try**：今後試したいこと、改善案

## 2. Keep（継続すること）

各シートで挙げられた、今後も維持したい機能や方針を整理した。

| 項目 | 内容 |
|---|---|
| 下書き・保存機能 | 履修登録の下書きを作成・保存できる機能 |
| 自動登録 | 登録作業の負担を減らすための自動登録機能 |
| 成績PDFの読み込み | 成績情報を取り込み、履修状況の確認に利用する機能 |
| 履修モデル | 履修計画の作成や単位状況の確認に用いるモデル |
| モデル生成機能 | 履修モデルを生成・提案する仕組み |

※ 自動登録はKPT上の継続案であり、学務システムとの連携方法が確定したことを意味しない。

## 3. Problem（問題点）

### 3.1 UI・操作性

- UIのデザインが定まっていない。
- UIの具体的な見た目やイメージが不足している。
- 履修モデルをどのように表示するかが決まっていない。
- 抽選科目の扱いが明確になっていない。

### 3.2 データ・システム

- 成績PDFをどのように取り込むかが決まっていない。
- データをどこに保存するかが決まっていない。
- データの取り扱い方針が不明確である。
- シラバスのデータ量が多い。
- 受け付けた情報をどのように管理するか検討が必要である。

### 3.3 履修モデル

- 履修モデルの表示方法が定まっていない。
- モデル生成に必要な情報や処理が明確になっていない。
- どの科目をおすすめするか、その判断基準が決まっていない。

## 4. Try（今後試すこと）

### 4.1 UI・UXの検討

- UIを決定する。
- UIの具体的なデザインを考える。
- ユーザーが使いやすい画面構成を検討する。
- 抽選科目の状況を提示する方法を検討する。

### 4.2 データの取り扱い

- データの保存先を決める。
- データの保存方法を決める。
- 成績PDFの取り込み方法を決める。
- シラバスなどのデータの取得・管理方法を検討する。

### 4.3 履修モデルの設計

- 履修モデルの全体的な仕組みを決める。
- 履修モデルの表示方法を決める。
- モデル生成の方法を検討する。
- 履修順序の決定方法を考える。

### 4.4 追加機能の検討

- 口コミ機能の追加を検討する。
- 科目選択を支援する情報の提示方法を考える。

## 5. KPTから見えた課題

複数のKPTを整理すると、主に次の4つの課題に分類できる。

| 分類 | 主な課題 | 今後の検討内容 |
|---|---|---|
| UI・UX | 画面構成や表示方法が未決定 | 画面設計、操作フロー |
| データ管理 | 保存先や取り込み方法が未決定 | データ構造、保存方式 |
| 履修モデル | モデルの生成・表示方法が未決定 | 判定条件、生成ロジック |
| 外部連携 | PDF・シラバス・学務システムとの連携 | データ取得方法、連携の実現可能性 |

## 6. 今後の進め方（整理案）

以下はKPTの内容をもとにした提案であり、チームで決定した開発計画ではない。

1. 下書き機能に必要な操作を整理する。
2. UIの画面構成と操作フローを決定する。
3. 履修モデルに必要なデータと判定条件を整理する。
4. データの保存先と保存形式を決定する。
5. 成績PDFやシラバスの取り込み方法を調査する。
6. 必須機能から順に実装し、動作を検証する。

## 7. まとめ

今回のKPTでは、下書き機能、成績PDFの読み込み、履修モデルなどを維持する方針が挙げられた。

一方で、UIの設計、データの保存方法、履修モデルの具体的な仕組みなど、実装に向けて決定する必要がある事項も明らかになった。

今後は、これらの課題を整理し、各機能の実現方法を検討することで、履修登録下書きアプリの具体的な設計につなげる。
