# ProjectBIG6 フロントエンド側からのデータ要求

## 1. 卒業要件・プログラム修了要件

卒業要件カードに表示するため、以下の情報がほしい。

- プログラムID（`program`）
- プログラム名（`programName`）
- プログラム修了判定（`status`、充足・未充足）
- 総合基礎部門
  - 選択必修科目
  - 合計単位数
- 専門教育部門
  - 理工基礎科目（指定科目・選択必修科目）
  - 必修科目
  - プログラム指定科目（◎・※・○）
  - 合計単位数

**各項目で必要な情報**

- 項目名（`name`）
- 必要単位数（`required`）
- 修得単位数（`earned`）
- 不足単位数（`missing`）
- 充足状態（`status`、充足・未充足）

部門は `sections` 配列、部門ごとの項目は `items` 配列で返す。不足科目数の扱いはバックエンド担当と相談する。

### JSONレスポンス例（DE、一部の項目を抜粋）

```json
{
  "program": "DE",
  "programName": "データエンジニアリング",
  "status": "未充足",
  "sections": [
    {
      "name": "総合基礎部門",
      "items": [
        {
          "name": "選択必修科目",
          "required": 10,
          "earned": 12,
          "missing": 0,
          "status": "充足"
        },
        {
          "name": "合計単位数",
          "required": 20,
          "earned": 20,
          "missing": 0,
          "status": "充足"
        }
      ]
    },
    {
      "name": "専門教育部門",
      "items": [
        {
          "name": "プログラム指定科目・◎科目",
          "required": 16,
          "earned": 14,
          "missing": 2,
          "status": "未充足"
        }
      ]
    }
  ]
}
```

## 2. 4つのプログラム

ユーザーがプログラムを選択・切り替えできるようにしたい。

- PC
- DE
- HM
- NS

**必要な情報**

- プログラム一覧（`programs`）。各プログラムのID（`id`）と名称（`name`）を含む
- 選択中のプログラムID（`selectedProgram`）

プログラムを切り替えた際は、切り替え先のプログラムIDに対応する卒業要件・プログラム修了判定を取得し、卒業要件カードの表示を更新する。

### JSONレスポンス例

```json
{
  "programs": [
    {
      "id": "PC",
      "name": "フィジカルコンピューティング"
    },
    {
      "id": "DE",
      "name": "データエンジニアリング"
    },
    {
      "id": "HM",
      "name": "ヒューマン・メディア"
    },
    {
      "id": "NS",
      "name": "ネットワークシステム"
    }
  ],
  "selectedProgram": "DE"
}
```

## 3. 履修登録下書き

時間割に科目を表示し、保存・再編集できるようにしたい。

**必要な情報**

- 科目ID
- 科目名
- 曜日・時限
- 単位数
- 履修登録下書きの内容（取得・保存）

## 4. 今後必要になる情報

- 履修可能な科目一覧
- 科目の検索・絞り込みに必要な情報
- 修得済み科目・成績情報
- 進級・研究ゼミナール・卒業研究着手・卒業の各判定結果

---

まずは **「卒業要件」と「4プログラムの切り替え」** を優先して連携したい。

レスポンスのデータ形式はJSONとする。APIのURLや内部の処理方法はバックエンド担当と相談して決定する。
